Session controls

Why Start, Boost, and Stop start out locked

The Peak Pro speaks a documented community protocol (Puffco calls the firmware platform “Lorax”): before any control works, the app must pass its challenge–response login, and every command travels as a framed packet. This build implements that login and framing exactly as published — proven against a mock device, byte-checked against the libraries — but the buttons arm only after the login succeeds and a read-back verifies against your real Peak Pro. No guessed commands are ever sent to a heating device.

    The Lorax login — how this app signs in

    Community-documented (puffco-py / puffcoble; authentication originally published by Fr0st3h), not published by Puffco. This app performs these steps on every connection — the seed is different every time, so reconnecting always means logging in again.

    1. Connect GATT and subscribe to notifications on the Reply characteristic.
    2. Write GET_ACCESS_SEED (opcode 0x00) on the Command characteristic.
    3. The device replies with a 16-byte random seed — different every connection.
    4. Token = the first 16 bytes of SHA-256(DEVICE_HANDSHAKE + seed). The handshake constant is a published, community-known value — the same for every device, not a per-device secret. This app uses the exact bytes from puffco-py's source, verified byte-identical against puffcoble's copy.
    5. Write UNLOCK_ACCESS (opcode 0x01) + token. A reply status of 0x00 means the login succeeded.
    6. Every read and write after that is a framed packet — [sequence][opcode][payload] — reads via READ_SHORT (0x10), writes via WRITE_SHORT (0x11), replies matched by sequence number.

    Lorax address book (VFS paths)

    Instead of one characteristic per value, Lorax multiplexes a virtual file system of paths over the single Command/Reply pair. This is the exact registry this app uses — every path copied from puffco-py's bundled specification and library source, then cross-checked against puffcoble. Where the two libraries spell a path differently, puffco-py's spelling is the one used and the other is listed as a read-only fallback or noted.
